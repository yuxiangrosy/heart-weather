# v0.3.0 周信/月信（Issue #3，待发布）

## 产品行为

- 沿用原回顾页统计与暖色像素视觉，新增天气信箱、小信详情和回小岛入口。
- 周一至周日为一周；自然月为一月。按设备本地日期与日记已有 `localDate` 归属周期。
- 已结束且有记录的周期，在下次打开 App 或从后台返回时生成。首次升级会整理已有历史；不假装后台定时运行。
- 零记录周期不新造空信；已有信件的记录全部删除后，保留同一封信并显示“已经没有心情记录”，清除旧引文和统计。
- 无弹窗、打卡、连续开信奖励或断更惩罚；未读仅提供温柔入口。
- 条数和天数分列；天气并列最多时一并展示；标签按条数计数。
- 少于 3 条或少于 3 个记录日不展示轨迹。其余仅列出每个记录日最后一次天气，不作好坏、原因或心理判断。
- 最多 3 段日记原话，默认隐藏；显示偏好可切换并随备份保存。
- 修改或删除日记的同一事务会先撤下相关信件旧引文，标记待更新；即使后续重新生成失败也不会继续展示已删除文字。
- 修改、移动日期、删除日记后，相关已结束周期按内容指纹重新生成，覆盖原周期信件并标记更新，不堆积重复档案。
- 信箱每页 10 封。旧信和旧岛屿均保留，不引入宠物/群岛范围。

## 持久化与兼容

- 保持 `heart-weather-db`、版本 1、原有四个对象仓库及 PWA 相对身份。
- 信件数组存于现有 `meta` 中 `key: weather-letters`，不迁移或清空日记。
- `letters.js` 纯函数负责周期/统计/文案；`app.js` 负责本地存储和 UI。未来可另加明确授权的总结提供者；本版无 AI 请求或密钥。
- 每个周期使用 `week:YYYY-MM-DD` / `month:YYYY-MM-DD` 稳定 ID；SHA-256 源内容指纹检测修改。
- 新增/更新信件增加备份修订号，信件与修订号同一事务保存。
- 完整 JSON 仍为 `mood-weather-backup` / `schemaVersion: 1`，使用已有预留字段 `data.reportSnapshots`。读取旧版缺失该字段或空数组的备份；无报告备份恢复后从日记生成已结束周期信件。
- 信件校验与日记校验都在覆盖恢复之前。完整备份包含明文引文，隐藏仅控制界面，不等于加密。
- Service Worker 新缓存包含 `letters.js`，只清理本 App 旧 shell，不操作 IndexedDB。

## 手机验收清单（仅隔离测试站点、合成记录）

必须使用不同 origin（域名或端口不同）的测试站点。同域下换路径、另建文件夹不构成 IndexedDB 隔离；也不依赖“再装一个图标”来保证隔离。

1. 打开小岛 → 信箱 → 周信/月信 → 返回小岛，动线顺畅，不弹窗催看。
2. 信件条数/天数、常见天气/标签符合合成日记；隐藏原话后不会在详情展示原话。
3. 修改旧记录后同一封信更新，断网重开仍可回看。
4. 先下载保护快照，再从文件 App 选择合成备份恢复；心情、景观、信件都保留。
